# HuaBu Infinite Canvas 对齐实施计划

日期：2026-09-11

## 目标与边界

唯一运行底座为 basketikun/infinite-canvas 的本地原始 Git 工作副本。
保留原生 DOM/SVG 画布、节点注册表、生成服务、localforage 存储和上游许可证。
HuaBuNova/HuaBu 仅是已验证领域能力的迁移来源，不恢复其编辑运行时。
卡藏用于工作流和视觉对照，不复制闭源实现、品牌或用户数据。

用户报告必须覆盖：拉线、右键创建、单击立即创建、整体 UI 与工作流差距。
更新：用户澄清内置浏览器后已成功观察登录画布、图片编辑器、创建菜单和资源库。
外部浏览器枚举仍有认证错误，内置浏览器可通过 iab URL 入口连接。
真实对照：左创建、底编辑、左下缩放、轻节点与下方参数编辑器；本地保留这些层级，不照搬浮层相互遮挡。

## 实施顺序

1. 交互核心：正反向连线、无效连接、Esc/失焦/指针取消、右键不拖动节点；创建菜单根据实际尺寸约束到视口。
2. 工作区布局：紧凑顶部项目区、左侧原生创建栏、按需展开素材/节点列表、底部编辑工具；390px 不挤压画布，面板有独立关闭入口。
3. 原生多工作画布：原生 CanvasProject 仍是唯一图文档，使用可选 workspaceId/sceneKind 关联工作画布，不嵌套第二套图模型。既有独立项目仍保持完整。
4. 场景链路：添加、改名、复制、切换、删除、持久化、整组原生归档导出与导入；复制重建节点和连线 ID，保留媒体存储引用。生成在途时不允许跨画布切换。
5. 自动化：添加独立且可重复的 Playwright 回归，测试浏览器与用户浏览器隔离；全新测试存储不接入生产 Provider。
6. 对抗验收：类型检查、构建、桌面/390px/短视口截图、布局可点击性、菜单边缘、连线保存、场景隔离、导入导出真实下载、console 与失败条件。

## 验收门槛

- 不以旧 Nova 测试通过代替新底座验证。
- 不以 scrollWidth 等于 innerWidth 代替实际可用性；检查按钮遮挡和面板关闭。
- 不以 toast 代替文件下载，不以 HTTP 500 或 mock 代替真实生成。
- 不自动读取/转换旧浏览器数据库，不丢弃未知节点，不导出 API key。
- 不清理用户项目或用户浏览器，不自动提交付费生成。
- 保留后续能力欠账，不能把本轮交付称为完整卡藏能力对齐。

## 继续阶段：画布库检索与信息密度

1. 在项目库保留“工作区根项目”视图，搜索覆盖根项目、工作画布和节点标题。
2. 在搜索入口旁展示项目、工作画布、节点和连线数量，让库页可以承担工作台总览，而不是只有卡片入口。
3. 搜索无结果时给出可恢复的空态；不修改本地项目数据、不把搜索状态写入业务存储。
4. 视觉沿用现有产品壳层和主题变量，桌面保持一行工具栏，小屏允许摘要换行但不挤压输入框。

### 本阶段验收

- 中英文文案 key 完整，`npm run typecheck` 通过。
- 搜索命中项目标题、工作画布标题和节点标题；清空搜索恢复全部根项目。

- 1440px、390px 和短高度视口无横向溢出、无遮挡。
