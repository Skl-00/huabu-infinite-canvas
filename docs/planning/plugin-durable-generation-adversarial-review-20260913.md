# 插件自定义生成 Durable Task 反方审查

## 结论

计划可以实施，但必须坚持“插件 API 兼容层 + 现有 runner 事实来源”这条边界。不能把插件脚本执行成功当作任务成功，也不能把结果回调当作持久化成功。

## 主要反对意见与处理

### 1. 插件 API 没有项目上下文

**风险**：任务能完成，但任务中心无法定位来源节点；插件自行传错 ID 还可能污染其他画布。

**处理**：宿主通过 `CanvasPluginHost` 提供当前运行上下文，`buildNodeContext` 自动绑定当前节点。外部插件仍可省略上下文，此时只允许创建无画布归属任务，不伪造来源。

### 2. 直接把脚本写入任务会泄露秘密

**风险**：脚本可能包含 API Key、私有 URL 或用户业务秘密，进入 localforage、导出或日志后难以清除。

**处理**：只保存渠道指纹、模型、能力和参数快照；重试通过当前配置解析脚本并校验指纹，不保存脚本正文。

### 3. 用当前配置重试会调用错误脚本

**风险**：用户修改渠道、模型或脚本后，任务中心重试可能把原任务绑定到新 Provider。

**处理**：复用现有 fingerprint/binding 校验；插件脚本任务的原渠道、格式、模型和脚本摘要变化时直接阻断，要求恢复原配置或创建新任务。

### 4. 插件视频无法刷新恢复

**风险**：模块级 Map 在刷新后为空，任务状态被误报为失败，结果丢失。

**处理**：插件视频生成统一由 `startVideoRun` 持久化；结果先进入 pending 或本地媒体存储，再标记 succeeded。移除 `pluginVideoResults` 作为事实来源。

### 5. 插件文本需要流式体验

**风险**：改成等待 runner 结束会破坏插件交互；每个 delta 全量写盘又会造成 IndexedDB 压力。

**处理**：保留 `onDelta`，复用文本 runner 约 120ms 的 partial 节流；最终结果写盘作为成功判定。

### 6. 结果回填可能覆盖新内容

**风险**：用户启动第二次生成或删除节点后，旧任务完成回调覆盖了新节点。

**处理**：`onCreated` 与完成回填都检查节点存在、当前 `generationRunId` 是否仍为该任务；节点不匹配时任务仍保留在任务中心，但不回写画布。

### 7. 插件结果类型不稳定

**风险**：脚本可能返回 URL、Blob、data URL 或自定义对象；不做校验会把 HTML/错误 JSON 当媒体保存。

**处理**：继续使用现有插件结果解析与媒体断言；只有本地媒体保存成功才进入成功状态，失败进入 pending/interrupted 或 failed。

### 8. 新增音频入口扩大风险面

**风险**：插件原先可能没有音频 API，新增后产生未覆盖的兼容行为。

**处理**：音频 API 只复用现有 `startAudioRun` 和 `AudioRun`，不扩展协议字段；没有配置或模型能力不匹配时沿用现有明确错误。

## 必须验证的反例

- localforage 第一次写入失败时，Provider 请求计数必须为零；
- 插件视频结果完成后刷新，任务中心仍能看到本地媒体或明确待保存状态；
- 修改脚本后点击重试必须阻断；
- 删除/复制节点后旧任务完成不能回写错误节点；
- 文本 Abort 后保留 partial，刷新不自动重跑；
- 任务记录和导出内容中不能出现 API Key 或脚本正文。
