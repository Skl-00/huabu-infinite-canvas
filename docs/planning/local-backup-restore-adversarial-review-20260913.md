# 本地数据备份恢复反方审查

## 主要风险

### 1. 把配置一起导出

备份只处理业务数据，不调用 `exportAppConfig`，也不包含 `useConfigStore`。恢复不会覆盖 API 渠道、Key 或脚本。

### 2. 媒体引用冲突

不能直接复用旧 storage key，否则会覆盖当前浏览器已有结果。导入必须为每个文件生成新 key，并递归替换画布、资产和任务中的旧 key。

### 3. 半途失败留下不完整恢复

在写入任何 IndexedDB 之前校验 `backup.json`、所有记录结构和每个文件路径。导入阶段媒体写入失败应立即停止，不能宣称恢复成功。

### 4. blob URL 失效

blob URL 只能在当前页面内使用，清单中必须保留 storage key，导入后通过 hydrate 重新生成 URL。

### 5. 任务 store 与 React 内存不一致

恢复后不能只调用 `setState`；必须写入四个 durable store、旧版历史 store，并调用对应 reload。

### 6. 旧版历史结构未知

旧版图片/视频历史只作为不透明 JSON 记录迁移，不把它们误当成新的 durable run。

## 通过条件

- 专项测试证明凭据不在清单、key 重写有效、刷新后数据仍可读；
- 全量测试通过；
- 文档明确备份不包含 AI 配置和云端同步设置。
