# 插件 Durable Generation 边界验收计划

## 日期

2026-09-13

## 背景

插件生成已经接入统一 durable runner，并完成了成功、刷新复用、任务来源和失败重试的主链验收。仍需要证明任务运行期间画布结构变化不会造成错误回写，也需要覆盖中断和部分成功这些高风险状态。

## 目标

- 插件图片任务在一个槽位失败、后续槽位成功时保存为部分成功，并保留逐槽位结果。
- 插件文本请求被 Abort 后保存为中断，保留已收到的 partial 内容，刷新不自动重新提交。
- 插件节点被删除后，原任务完成只能写入任务仓储，不能写入不存在的节点或误写其他节点。
- 复制包含插件节点的画布后，副本不继承旧的 generationRunId，也不会因插件重新挂载而重复提交原任务。
- 所有新增证据继续断言来源上下文和凭据隔离，不把脚本正文或 API Key 写入任务记录。

## 执行步骤

1. 读取现有插件 host、四类 runner、画布复制逻辑和专项 Playwright 约定。
2. 编写反方审查，列出状态迁移、竞态、刷新、任务仓储和敏感信息的失败模式。
3. 先增加能复现边界的浏览器验收；只有测试暴露真实行为缺陷时才修改生产代码。
4. 串行运行专项测试、类型检查、构建和全量 Playwright。
5. 做差异检查、敏感信息审计和工作树审计，并更新进度冷存档。

## 验收标准

- 部分成功任务的成功槽位结果和失败槽位错误均可读取，且不会因插件回调只取第一张图而丢失任务事实。
- Abort 任务最终状态为 `interrupted`，partial 内容仍可在任务中心和刷新后读取，Provider POST 次数保持不变。
- 删除目标节点后，任务可以完成，但新建的其他节点没有继承内容或运行 ID。
- 复制场景中的插件节点拥有新的节点 ID，且没有旧任务身份；副本挂载不产生额外 Provider POST。
- 失败、中断、部分成功、复制和删除的证据均不泄露 API Key、插件脚本正文或含凭据 URL。
