# 实施前对抗审查

日期：2026-09-11

1. 另建场景图模型是否背离底座？采用多个原生 CanvasProject 的轻量关联，编辑器和生成器不替换；不同时维护两份 nodes。
2. 老项目没有 workspaceId 会否丢失？用项目自身 ID 作为工作项目身份，字段可选；添加场景时只关联该组，不扫描旧应用。
3. 克隆是否继承活动任务和错误来源？重建节点/边/groupId，复制不带聊天和未完成任务 ID；不把 loading 节点当继续运行。
4. 切换前保存是否靠延迟猜测？在导航前同步更新原生 store 当前快照；各画布路由组件重新挂载，历史和选择不串场。
5. 导入是否误合并现有项目？归档每次导入重新映射 workspaceId 和项目 ID，组内关联保留；未知扩展节点保留。
6. 删除是否悄悄丢整组？单工作画布删除有确认，最后一张禁止在场景菜单删除；项目级删除明确整组。
7. 小屏是否只是藏滚动条？创建栏常驻窄栏，列表在小屏覆盖而非挤压；顶部可收缩，编辑和缩放错开，无空白 300px 偏移。
8. 菜单高度是否猜测？用实际 DOM 尺寸与 ResizeObserver，位置上下界 clamp，过高滚动，Esc 和外部点击均可关闭。
9. 指针事件是否重复提交？连接使用指针事件并跟踪发起 pointerId；mouse 只保留原生节点拖动，右键禁止启动拖动，取消清理选择框和连接。
10. 接入真实站点受阻是否终止全部工作？截图精确对照保留阻塞，源码、布局和可测交互继续；不声称已观察登录后行为。

审查结论：允许按计划落地。多画布归档、运行中导航、手机遮挡是重点找茬项。

## 继续阶段对抗审查

1. 搜索是否误把工作画布渲染成重复根项目？根项目只取没有有效父级的项目，卡片内部再聚合同组工作画布。
2. 搜索节点标题是否触发空值异常？标题字段按可选值处理，关键词统一 trim 和小写化。
3. 统计是否与搜索结果混淆？统计明确表示全部本地库，不能随搜索结果变化。
4. 小屏摘要是否挤压搜索框？工具栏使用可换行布局，输入框拥有最小宽度和完整宽度约束。
5. 空态是否只是不可操作文本？保留清除搜索的输入控件，且空态明确说明搜索范围。

审查结论：本阶段只改变画布库查询与展示，不触碰画布文档、生成调用和本地存储协议，风险可控；通过类型检查和三种视口验收后再进入下一批能力。
