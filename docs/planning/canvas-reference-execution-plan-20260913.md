# 画布参考资源真实执行链计划

## 目标

把画布中的“参考资源连接”从仅在节点 UI 中显示，修复为可被生成编译器稳定收集、从本地持久化媒体恢复、转换成 Provider 可接受的请求输入，并在断开连接后立即移除。

## 范围

1. 统一资源有效性判定：图片、视频、音频节点存在 `storageKey` 或可用内容地址时都可以进入执行图；文本节点保留内容/提示词判定；插件资源沿用 Node Registry。
2. 在执行前统一 hydrate：
   - 图片优先从 `storageKey` 读取 Blob 并转换为 data URL；
   - 无持久化键时使用可读取的 `data:`、`blob:` 或远程 URL；
   - 视频/音频保留可供适配器读取的本地键和 URL。
3. 保持四类输入语义：
   - 直接连接到生成节点；
   - 通过 Config 节点聚合输入；
   - 通过 Group 节点展开输入；
   - 同一资源多次连接时按节点 ID 去重。
4. 让文本生成、多模态文本、文生图/图生图和视频参考都使用同一份编译后的上下文，避免参考栏与 Provider 请求各走一套逻辑。
5. 增加请求体级别的浏览器测试，断言实际发送的 multipart、OpenAI-compatible message、Agnes/Gemini 输入包含参考资源，而不只断言参考栏出现。

## 实施顺序

1. 阅读当前资源解析、媒体存储、生成 API 和上游同名模块，记录差异与不变量。
2. 修复 `canvas-resource-references` 与 `canvas-node-generation` 的资源判定和读取逻辑。
3. 修复参考缩略图在恢复后只剩 `storageKey` 时的展示 hydrate，避免 UI 与执行状态分裂。
4. 为图片 storage-only、直接连线、Config、Group、断线和刷新恢复补充专项测试。
5. 更新功能进度、待测项和变更记录。
6. 执行类型检查、专项 Playwright、单元测试、构建和 diff 检查；失败时按根因修复后重跑。

## 不变量

- `storageKey` 是本地媒体的持久身份，不能因为 `content` 为空而丢弃资源。
- 参考栏显示的每个可执行资源必须能在提交前被编译器解析，解析失败要阻止提交并给出错误。
- 请求体中必须出现真实图片输入；Provider 返回成功不能替代请求体证据。
- 断开连接后资源不得继续进入新执行请求。
- 不写入 API key、Authorization、模型脚本或用户凭据。
- 不复制卡藏闭源实现，只吸收公开可观察交互和上游 MIT 项目的协议思想。

## 完成标准

- storage-only 图片经过刷新恢复后仍可作为参考执行。
- 直接连接、Config、Group 三种路径请求体均带有正确资源，且重复资源只发送一次。
- 文本多模态、图像编辑和视频参考均从同一连接图得到输入。
- 断开连接后的新请求不再包含该资源。
- 类型检查、专项测试、全量测试、构建和 `git diff --check` 通过。
