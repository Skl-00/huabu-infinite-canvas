# HuaBu Infinite Canvas 底座替换计划

日期：2026-09-11
基线：`basketikun/infinite-canvas`，commit `d213a74614e0e4bd8a26383d1e1e907249e9c61b`，v0.18.0
工作目录：`D:\codex\HuaBuInfiniteCanvas`

## 目标

将 `basketikun/infinite-canvas` 的真实源码作为 HuaBu 画布的产品底座，保留其画布、节点、连线、菜单、项目、素材、配置、生成和插件边界。旧 `D:\codex\HuaBuNova` 只作为待迁移能力与数据来源，不再作为新画布运行时的基础。

第一阶段必须直接解决已报告的四个用户可感知问题：

1. 连线拖拽后形成真实、可见、可保存的连接；
2. 画布空白处右键出现节点创建菜单；
3. 点击左侧创建项后立即在合理画布位置创建节点，不需要额外点击画布；
4. 保持上游的整体 UI、交互密度和工作流，不重新套用 Nova 的旧界面。

## 执行阶段

### 0. 保护与基线

- 保留旧应用、旧项目、浏览器本地数据和用户未提交修改，不覆盖或迁移原文件。
- 保留上游 Git 历史、MIT License、作者信息和前端标识。
- 固定上游 commit，暂不盲目跟随远端 `main`。
- 安装 `web` 锁定依赖，记录基线构建和实际启动端口。

### 1. 上游行为验收

- 在独立端口启动真实上游应用。
- 验证项目创建、节点创建、拖拽移动、缩放/平移、撤销重做、持久化、素材/配置入口。
- 分别验证已有连线、从端口拖到空白处的创建菜单、背景右键菜单、左侧创建按钮的即时创建。
- 验证桌面视口和 390px 视口；检查控制台、DOM 边、横向溢出和刷新恢复。
- 任何“界面看起来有”但状态、DOM 或刷新后不存在的行为均视为未通过。

### 2. 底座内的最小修复

- 只在上游组件、store 和页面编排的既有边界内修复四个明确问题。
- 连线使用上游的 handle/edge/store 流程，不增加另一套图模型。
- 右键菜单复用上游 `CanvasContextMenu` 与注册表创建流程。
- 左侧创建动作直接调用上游 `createNode`，位置由当前 viewport/可见中心和已有节点布局计算得到。
- 为每个修复添加针对性测试或可重复的浏览器验收证据。

### 3. HuaBu 能力边界映射

- 逐项盘点 Nova 的多场景、共享资产/版本、镜头顺序、CapCut ZIP/preflight、`.huabu` 归档、Provider 作业和结果资产。
- 将能力分成：可直接落在上游节点插件/节点 metadata 的内容、应落在项目/素材服务的内容、暂不迁移的旧运行时内容。
- 不做静默的旧数据转换，不把 API key 写入项目导出，不把导出 JSON 冒充真实执行。
- 先迁移一个可验证的最小纵切能力，再扩大范围；每个能力必须有输入、输出、保存位置和验收标准。

### 4. 真实工作流增强

- 在上游生成节点/素材/配置能力之上接入 HuaBu 的真实 Provider/job/asset 边界。
- 生成、导出、任务状态和结果资产分别建模，禁止用 toast、下载 JSON 或假状态代替真实成功。
- 对 Provider 未配置、请求失败、跨域、超时和结果不可持久化建立可见失败状态。

## 退出条件

- 上游应用能在新工作目录独立启动；旧 Nova 未被覆盖。
- 四个已报告交互问题在浏览器中可重复通过，且与持久化状态一致。
- `npm run typecheck`、`npm run build` 和针对性测试通过。
- 390px 无横向溢出；控制台无由本次改动引入的错误。
- 迁移能力有明确清单；未完成项诚实记录，不以“视觉相似”宣称对齐。

## 明确不做

- 不继续在 `HuaBuNova` 上修补后再伪装成上游底座。
- 不复制闭源卡藏代码、品牌或受限实现。
- 不删除、覆盖或批量改写旧项目和浏览器本地数据。
- 不在没有真实 Provider 成功结果时声称生成链路已端到端完成。
