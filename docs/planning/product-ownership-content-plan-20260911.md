# HuaBu 产品归属与内容重建计划

更新时间：2026-09-11

## 目标

让新仓库和站点在用户可见层面明确属于 HuaBu：品牌、产品定位、README、文档首页、导航、安装说明和联系方式不再继续使用上游项目的产品叙述或商业内容。

## 本轮范围

1. 统一 Web 应用和文档站的产品名为 `HuaBu 画布` / `HuaBu Canvas`。
2. 重写根 README，只保留 HuaBu 当前真实能力、底座来源、运行方式、贡献入口和已知边界。
3. 重写文档站首页、文档索引、顶部分类和关键快速开始/功能说明。
4. 将项目自身 GitHub、问题反馈和贡献入口指向 `Skl-00/huabu-infinite-canvas`。
5. 保留上游许可证、底座来源说明、`infinite-canvas` MCP/包名、第三方提示词来源和数据兼容键，避免破坏运行时协议。

## 对抗性审查

- 不做机械全局替换：`infinite-canvas` 作为 npm 包名、MCP 名称、localForage 数据库名和插件 SDK 命名空间必须保留。
- 不保留上游赞助商、原作者联系方式、原社区群和上游项目效果展示，避免形成归属误导。
- 不把尚未实现的真实 Provider、云同步、商业化、账号积分或卡藏私有能力写成已支持功能。
- 不抹去上游许可证与来源，README 和文档明确说明本项目基于上游底座继续开发。
- 产品品牌变更不改变路由、导出协议、MCP 工具名、浏览器本地存储键或已有自动化选择器。

## 验收标准

- Web 页面标题、顶栏品牌、默认画布名和关键设置文案显示 HuaBu。
- README 和文档首页不再出现上游赞助商、原作者联系方式或上游项目专属社区入口。
- 项目自身 GitHub 入口全部指向新仓库，第三方来源链接保持原样。
- `npm test`、`npm run typecheck`、`npm run build` 通过。
