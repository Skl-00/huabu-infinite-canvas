# HuaBu Infinite Canvas 底座计划反方审查

日期：2026-09-11
对应计划：`huabu-infinite-canvas-foundation-plan-20260911.md`

## 主要反对意见与处置

### 1. “换成上游”仍可能只是复制代码

风险：工作目录虽然来自上游，后续又把 Nova 的页面、store 和 CSS 大量搬回，最终重新形成两个互相冲突的画布系统。

处置：第一阶段只允许修改上游已有画布边界；Nova 只产生能力映射表。任何跨边界迁移必须先定义上游对象、持久化位置、失败语义和测试。

### 2. 上游已有交互可能被误判

风险：连线、右键和即时创建的真实行为不能根据源码名字推断；尤其背景右键是否打开创建菜单、连线是否仅有预览，都必须运行时验证。

处置：每项同时检查用户动作、store 状态、React Flow DOM 和刷新结果。未运行验证前不得写成“已修复”。

### 3. 修复右键可能破坏节点菜单与浏览器菜单

风险：全局拦截 `contextmenu` 会让节点上下文菜单、输入框编辑、浏览器可访问性和插件节点异常。

处置：仅对画布 pane 且不在节点/控件上的右键打开创建菜单；节点右键继续走节点菜单；输入、文本编辑和菜单自身不拦截。

### 4. 即时创建可能产生重叠或错位

风险：左侧按钮直接创建节点时使用屏幕坐标，会因 zoom、pan、侧栏宽度和窗口尺寸导致节点在视口外或重叠。

处置：使用上游 viewport transform 将可见中心转换为画布坐标，并根据现有节点矩形计算空位；创建后保持节点初始化和可见性。

### 5. 连线“可见”不等于“可用”

风险：DOM 中有 edge，但 store 没有保存；或 edge 保存了却没有端口语义，刷新后消失。

处置：验证兼容端口、edge DOM、项目持久化和刷新恢复；删除节点时验证关联 edge 级联删除。

### 6. 迁移旧数据的隐形破坏

风险：自动导入 Nova 的 IndexedDB/JSON 会覆盖或丢失项目、凭据、资产二进制和版本关系。

处置：本阶段不自动迁移；先生成只读盘点和字段映射，用户明确批准后再做可回滚、备份优先的导入。

### 7. 旧 Provider 结论污染新底座

风险：把 Nova 中的 HTTP 500、模拟结果或导出文件当作上游真实生成能力。

处置：生成与导出分离；只有真实 Provider 返回并持久化结果资产/结果节点才算成功，失败要保留具体错误和恢复路径。

### 8. 依赖与上游漂移

风险：网络安装、远端 main 或锁文件差异导致无法复现，或者当前机器端口被其他应用占用。

处置：锁定当前 commit 和 lockfile，记录安装命令与版本；启动前检查端口，使用独立未占用端口，不关闭用户已有服务。

## 阶段闸门

- G0：新工作副本与旧应用路径分离，git 状态干净。
- G1：未改代码前，上游基线可构建并可启动。
- G2：四个交互修复分别有运行时证据。
- G3：核心检查通过，且 390px、控制台、持久化没有回归。
- G4：任何自有能力迁移都有明确边界和单独验收；否则停留在盘点，不假装完成。

## 结论

计划可以执行，但必须坚持“上游源码优先、运行时证据优先、迁移分阶段、旧数据不触碰”四项约束。若某项修复需要重写上游核心模型，应退回设计审查，而不是在两个画布模型之间继续打补丁。
