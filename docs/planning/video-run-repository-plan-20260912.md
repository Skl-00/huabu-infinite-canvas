# 视频任务仓储与跨标签协调计划

## 目标

将视频生成从 `video` 页面私有历史提升为独立、可恢复的浏览器本地任务记录，解决刷新、页面切换和多个标签页下的任务事实不一致问题。

## 设计

- 每个任务保存版本、修订号、状态、创建/更新时间、冻结的提示词、模型、渠道身份、视频参数、参考素材、远端任务身份和结果媒体。
- 任务状态使用 `queued`、`running`、`succeeded`、`failed`、`interrupted`。
- 以 `localforage` 作为持久事实，以 `BroadcastChannel` 通知其他标签页刷新。
- 以 Web Locks 抢占单个任务的执行权；没有锁能力时拒绝开始执行，不把同一视频任务交给多个标签页。
- 页面刷新后只恢复有远端任务身份的记录；没有远端 ID 的 queued/running 记录标为 `interrupted`，禁止自动重新提交。
- 轮询始终使用任务保存的原渠道绑定和冻结配置；密钥可轮换，协议、地址、模型或脚本变化时停止查询。
- 失败重试创建新任务记录并保留 `retryOf`，不覆盖原失败证据。

## 实施顺序

1. 建立 `VideoRun` 领域类型、状态迁移和独立仓储。
2. 建立视频执行器：提交前持久化，锁内提交，状态和结果逐步持久化，恢复时继续原任务。
3. 将视频工作台接入仓储，保留现有历史记录的可读兼容；任务中心统一显示图片与视频任务。
4. 增加跨标签、刷新中断、原任务恢复、失败重试和媒体持久化测试。
5. 更新文档和验收记录，串行执行类型检查、定向回归、完整回归和构建。

## 反方审查

- 不把页面 React 状态当作事实；所有 Provider 请求前后先写仓储。
- 不用全局单锁阻塞不同任务；锁名按任务 ID 隔离，但视频生成仍遵守现有页面单任务约束。
- 不在未知提交状态下自动重发；没有远端 ID 的任务只显示待核对。
- 不让删除历史删除共享素材；任务结果和素材库使用独立引用。
- 不把生成耗时当视频片长；媒体元数据只在实际下载后更新。
- 不偷偷扩大超时、轮询次数、重试次数、并发或上传能力边界。

## 验收标准

- 同一任务在两个标签页只允许一个执行者，另一个标签页能收到最新状态。
- 刷新后有远端任务 ID 的记录继续查询，不产生第二次 POST。
- 提交前持久化失败时 POST 次数为 0。
- 查询中断显示待核对，明确失败才能重试；重试保留原任务并生成新记录。
- 成功媒体在任务记录中可刷新恢复，删除任务历史不删除共享媒体。
