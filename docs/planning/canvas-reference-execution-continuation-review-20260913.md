# 画布参考执行链续作对抗审查

## 主要风险

1. Config 连线方向如果继续依赖单条 `find`，多个 Config 或多个聚合输入可能静默丢失。
2. Group 既可能作为整体连接，也可能成员直接连接，若不在编译入口统一去重，Provider 会重复收到同一资源。
3. `@` 引用只替换提示词而没有同步过滤媒体，会造成“文字看似引用，实际发送了所有参考”。
4. 恢复时执行链能读取 `storageKey`，但参考栏仍使用空 `content`，会让用户误以为资源无效。
5. Provider 返回成功不能证明视频参考字段正确，必须断言真实 multipart/JSON 请求体。
6. Agnes 只能接收公开 URL 的参考媒体，本地 `storageKey` 必须在提交前明确失败，不能上传到未知图床或泄露凭据。

## 审查结论

- 资源收集应采用“直接输入 + 所有连接 Config 输入”的集合模型，而不是单条 Config 特判。
- Group 展开、节点 ID 去重和显式引用过滤必须在同一层完成。
- 恢复 hydrate 只改善本地展示和读取，不改变持久化真相，不把临时 URL写回项目。
- 测试必须覆盖成功请求体和断线、缺失资源、Agnes 本地资源拒绝等失败路径。
