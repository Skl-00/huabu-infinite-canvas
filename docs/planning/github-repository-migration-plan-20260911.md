# HuaBu Infinite Canvas GitHub 仓库迁移计划

更新时间：2026-09-11

## 目标

为当前基于 `basketikun/infinite-canvas` 开发的 HuaBu Infinite Canvas 创建并使用自己的 GitHub 仓库，站内 GitHub 入口、README、部署说明和远程 Git 地址统一指向新仓库。

## 执行顺序

1. 检查当前 Git 状态、远程地址和站内上游仓库引用。
2. 检查 GitHub 登录账号及目标仓库是否已存在。
3. 若目标仓库不存在，创建公开仓库，不覆盖同名已有仓库。
4. 先修正站内 GitHub 入口、README、文档部署引用和包元数据，再提交本地变更。
5. 将当前分支推送到新仓库，设置新仓库为 `origin`，保留上游仓库为 `upstream`。
6. 重新检查远程地址、工作区状态、构建与核心回归。

## 对抗性审查

- 不会覆盖或删除用户账号下已有的同名仓库。
- 不会把 API Key、登录凭据、浏览器本地数据或生成资产推送到 GitHub。
- 推送前检查 `.gitignore`、未跟踪文件和敏感字段；`web/test-results` 等验收产物不作为业务源码发布。
- 不会把所有第三方提示词来源链接误改成新仓库；只替换属于本项目仓库、徽章、部署入口和插件安装说明的上游引用。
- 新仓库创建成功不等于部署成功；部署和真实 Provider 生成仍分别验证。
