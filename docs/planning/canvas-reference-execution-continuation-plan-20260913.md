# 画布参考执行链续作计划

## 目标

在上一轮已验证的图片参考执行基础上，补齐 Config、Group、显式 `@` 引用和视频多媒体参考的统一输入协议，使参考栏显示、编译上下文和 Provider 请求体保持同一份真实数据。

## 实施范围

1. 统一直接输入、Config 聚合输入和 Group 展开输入的方向与去重规则。
2. 覆盖普通提示词与 `@[node:...]` 混合时的显式资源选择，不让未选择资源隐式进入请求。
3. 恢复后为图片、视频、音频参考补齐可展示的本地 URL，避免 UI 只有图标而执行链已有资源。
4. 为 OpenAI-compatible、Gemini 和 Agnes 视频请求增加请求体级测试，明确本地媒体限制和失败前置条件。
5. 不改变用户已有截图修改，不写入任何 API key 或凭据。

## 执行顺序

1. 先修资源收集协议并增加纯函数专项测试。
2. 再修恢复态参考预览的 hydrate 入口。
3. 补真实 Provider 请求体测试与断开/重复/混合引用负向测试。
4. 运行类型检查、专项测试、全量测试、构建和 diff 检查。
5. 更新进度文档与变更记录，提交并推送。

## 不变量

- 连接方向始终为资源或 Config 输入 `fromNodeId` 指向执行目标 `toNodeId`。
- Config 是输入聚合节点，不把执行目标自身误当成 Config 的资源输入。
- Group 只展开其成员资源，组引用和成员直连按节点 ID 去重。
- 有显式 `@` 引用时，只发送被引用资源；普通提示词仍然保留。
- 无显式引用时，发送连接图编译出的全部资源。
- 断开连接后，参考栏、编译上下文和新请求均不再包含该资源。
- Agnes 对本地参考素材继续前置拒绝，不伪造“已发送”。

## 完成标准

- Config 聚合多个输入、Group 输入、混合文本和图片、重复连接均有测试证据。
- 恢复后的缩略图与真实可执行资源一致。
- 视频请求体能分别证明 OpenAI、Gemini 的图片/视频/音频输入字段。
- 类型检查、专项测试、全量测试、构建和 `git diff --check` 通过。
