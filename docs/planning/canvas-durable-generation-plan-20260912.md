# 画布持久生成接入计划

## 目标

将画布中的图片和视频生成接入已经验证的 `ImageRun` / `VideoRun` 执行器，让 Provider 请求、刷新恢复、跨标签协调、结果媒体留存和错误边界与工作台保持一致，同时保留画布节点、连接、场景隔离和撤销栈语义。

## 本阶段范围

- 画布图片生成和图片编辑复用 `startImageRun`，视频生成复用 `startVideoRun`。
- 任务记录增加画布来源上下文：项目、场景、目标节点和运行节点。
- 任务开始前仍先保存任务；画布只把任务状态和结果投影回节点，不把任务事实塞进撤销/重做历史。
- 刷新后由全局任务恢复机制继续 Provider 任务；画布打开后从任务记录回填仍存在的目标节点。
- 画布删除节点、切换场景或复制场景不得删除任务记录，不得复制原执行身份。
- 画布对文本、音频、自定义插件生成保持现有执行路径，另立阶段处理。

## 设计约束

- 不在画布层再次实现轮询、跨标签锁、凭据快照或重试。
- 任务记录只保存无凭据的渠道绑定和冻结参数；API key 继续从当前配置解析。
- 画布上下文只保存项目/场景/节点 ID，不保存完整画布快照。
- 任务结果先进入媒体存储，再回填节点；节点回填失败时任务结果仍可在任务中心恢复。
- 运行中的请求不进入画布撤销栈；用户停止只取消当前页面控制器，不自动删除已提交远端任务。
- 复制场景生成新节点 ID，不能继承 `canvasRunId`、远端任务 ID 或运行中状态。

## 实施顺序

1. 扩展图片/视频任务类型和执行器输入，记录画布上下文。
2. 将 `project.tsx` 的图片/视频提交与轮询替换为执行器调用，保留节点投影。
3. 打开场景时从任务记录恢复目标节点；节点已删除时保留任务但不创建幽灵节点。
4. 更新画布复制、删除、清理和 Agent 状态边界。
5. 增加刷新、导航、双标签、结果回填、任务保留和场景复制测试。

## 反方审查

- 画布节点状态不是任务事实；节点丢失不能让任务记录丢失。
- 任务中心成功但节点回填失败时，必须显示可恢复结果，不能把任务标为失败。
- 同一节点重复点击只能复用或拒绝已有运行，不能创建两个 Provider 请求。
- 场景复制不得复制执行身份；场景删除不得连带删除共享媒体。
- 画布切换不得中断或重发已提交请求；停止操作只影响本页面等待，不改变远端事实。
- 旧画布节点只有远端 task ID 而没有独立任务记录时，继续保持原有“手动恢复查询”兼容，不猜测生成配方。

## 验收标准

- 画布图片/视频请求使用独立任务记录，提交前持久化。
- 刷新、切换场景和第二标签页不会重复 POST。
- 任务完成后节点能回填结果；节点删除后任务仍能在任务中心查看。
- 复制场景不会复制任务身份；任务引用的媒体经过清理仍可用。
- 类型检查、画布回归、图片/视频任务回归和构建全部通过。
