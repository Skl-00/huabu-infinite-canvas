## 实施顺序

1. 显式 Agnes 渠道协议及三模型预设，保留其它渠道和用户配置。密钥只存本机浏览器配置，不写源码、计划、测试、报告或 Git。
2. 独立 API 适配，现有 OpenAI/Gemini/脚本调用优先级不变。直接复用图片任务和视频/画布 API 入口。
3. 视频任务冻结原渠道身份，轮询不跟随当前渠道，允许同一渠道密钥轮换，渠道地址/模型/协议改变时停止且提示。工作台提交前保存记录，恢复查询不新建视频任务，存素材等待落库。
4. 用受控响应验证字段、任务 ID、失败/未知状态、刷新恢复和错误脱敏。单独串行调用三个免费模型，真实输出与本地保存分开记录；遇到 429 不自动重复生成。
5. 类型检查、完整浏览器回归、构建串行执行，桌面/手机截图检查；更新待测/待办/CHANGELOG 及恢复点。

## 边界

- 不增加付费模型、不更换模型、不批量实测。
- 不擅自改变现有轮询次数、间隔、超时、重试或全局并发配置。官方字段转换是协议适配，不静默裁剪参考媒体或时长；不支持的输入明确报错。
- 不把用户本地图片上传到未经授权的第三方图床。Agnes 视频参考图需要公开链接，缺少上传服务属于明确残余能力。
- 内置浏览器工具当前返回认证错误。独立测试浏览器的配置不能当作用户日常浏览器配置；如能通过可用浏览器 UI 完成，记录实际目标。
- 不提交或推送 Git，不创建额外任务。

## 多维度反方审查

| 质疑 | 处理和验收 |
| --- | --- |
| 只加三个名字，还是发旧协议 | 显式 apiFormat + 请求字段断言 + 真实 API |
| 免费 Flash 被同名付费视频替代 | 三模型固定预设；每次实测核验请求模型 |
| 视频用 task_id 查询造成永远排队 | 独立保存 videoId，检查查询 URL |
| 用户改渠道后旧任务向新服务器泄露 ID/密钥 | 无密钥 origin binding；严格原渠道校验后才请求 |
| 网络失败后误点重试产生第二条任务 | 保留已知 task，提供继续查询；不自动重提交 |
| 刷新时 POST 未知结果被判已失败 | 提交前日志；没有远端 ID 的中断提示需核对 |
| URL 暂时可用就声称本地保存 | 检查 Blob 字节、媒体尺寸、storageKey、刷新预览 |
| 密钥被错误响应/截图/trace 记录 | 统一脱敏，真实测试关闭 trace，只记白名单结果 |
| 模拟回归冒充真实生成 | 两类证据分开；未成功模型记录实际阻断 |
| 无限扩大范围导致接入没收尾 | 本轮交付三模型与视频可靠恢复；其它缺口留待办 |

结论：按上述边界实施，无需重写底座或另造 Provider 后端。
