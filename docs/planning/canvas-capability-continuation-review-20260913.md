# 画布能力续作对抗审查

## 已发现的风险

1. 当前 `normalizeConnection` 禁止 Config 作为 source，因此上一轮只验证 Config -> 目标会留下不可由用户创建的“假闭环”。
2. 参考栏只保存资源节点 ID 不够，聚合输入必须同时保存真实连接的目标节点，否则移除动作可能保留仍然生效的连接。
3. 仅验证编译函数不能证明面板、连接、断开和执行入口使用同一语义。
4. 兼容导入数据时不能破坏当前 UI 的方向规则，也不能让同一资源因双向兼容分支重复发送。

## 反制方案

- 以连接图为唯一真相，收集 Config 时同时查找目标节点指向 Config 和 Config 指向目标节点的连接。
- 参考栏使用 `{ sourceNodeId, connectionTargetId }`，显示资源节点，断开真实边。
- 测试同时覆盖当前 UI 方向和兼容方向，并覆盖直接连接、Group、重复资源。
- 完成后再次检查四类生成入口和 Provider 请求体，避免“测试 helper 通过、主流程不通”。
