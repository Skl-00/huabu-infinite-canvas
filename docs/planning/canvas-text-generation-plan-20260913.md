# 画布文本持久生成计划

## 目标

把画布文本生成从当前流式直写节点的路径迁移到独立的 `TextRun` 持久任务仓储，使文本生成具备提交前落盘、跨刷新可识别、失败可重试、结果可恢复、任务中心可查看和节点删除后任务仍保留的能力。

## 现状审查

- 图片、视频、音频已经有独立 durable run；文本仍由画布生成组件直接消费流式响应并写入节点。
- 文本输出可能是长内容，不能把完整画布快照或 Provider 密钥写进任务记录。
- 流式协议不能假设远端可续查；页面中断时必须标记 `interrupted`，禁止自动重复提交。
- 文本不产生媒体文件，结果应落在任务仓储并通过画布上下文重新投影到文本节点。
- 旧文本节点和插件文本节点必须保持兼容，不能破坏历史人工内容。

## 实施顺序

1. 读取现有文本 API、流式解析、画布文本入口和任务中心数据模型。
2. 定义 `TextRun` 请求快照、状态、结果、错误和画布上下文。
3. 实现 localforage 仓储、Web Locks、BroadcastChannel、提交前落盘和中断恢复。
4. 将画布新建文本与重试路径切换到 `TextRun`，保持流式增量显示。
5. 增加任务中心文本页、搜索、过滤、复制/下载和重新投影。
6. 用故障注入验证零重复提交、错误脱敏、刷新恢复和冻结参数重试。

## 反方审查

- Provider 请求必须在初始任务记录成功后开始；保存失败时不得请求。
- 流式增量写入只能作为 UI 快照，最终结果必须独立持久化。
- Abort、页面刷新和连接中断不能默认当成 Provider 失败；没有续查协议时标记 `interrupted`。
- 重试必须创建子任务，不能覆盖旧文本或旧错误证据。
- 任务记录不能包含 API Key、完整配置对象或完整画布快照。
- 画布节点删除、场景复制和历史节点必须与图片/视频/音频保持一致的身份边界。

## 验收标准

- 文本 Provider 请求前可读取 `TextRun`。
- 成功、失败、中断、重试状态可在任务中心查看。
- 刷新不会重复提交；成功文本可重新投影到目标节点。
- 画布原有流式体验和插件文本能力不被破坏。
- 类型检查、定向 E2E、全量回归、构建和差异审计通过。
