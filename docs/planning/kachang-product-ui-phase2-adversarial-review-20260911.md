# 卡藏式产品整体 UI 第二阶段对抗审查

日期：2026-09-11

## 风险与处理

1. 主页重做会不会丢失已有入口？
   - 处理：保留画布、图片、视频、素材、提示词、配置和 Agent 的直接入口；只改变布局，不删除路由。

2. 全局壳层统一会不会覆盖画布专用顶栏？
   - 处理：画布项目页继续隐藏通用顶栏，使用自己的项目顶栏；其他页面共用产品壳层。

3. 为了像卡藏而复制云同步/积分能力？
   - 处理：只呈现本地真实能力；云同步、积分、账号继续使用现有实现或明确不显示为已实现。

4. 页面统一是否会损坏已有生成流程？
   - 处理：生成逻辑和服务调用不改，先做布局容器、操作栏和结果区重排；所有生成相关组件保留原 props 与状态。

5. 手机端是否只是把桌面布局压缩？
   - 处理：一级页面在 390px 使用上下分区、抽屉或 sticky 操作栏；不要求三栏同时存在。

6. 统一主题是否会继续使用单一石色/深色？
   - 处理：使用中性背景、青绿色强调、橙色警示和少量蓝色操作色；组件通过 CSS 变量继承主题。

7. 页面是否会变成过度装饰的营销首页？
   - 处理：主页第一屏使用任务入口和最近工作，不设置巨大 hero、装饰性圆球或说明卡片堆叠。

8. 视觉验收是否掩盖不可用状态？
   - 处理：每个入口至少验证 URL、按钮可用性、空状态、错误状态和主要面板；构建成功不等于工作流成功。

## 结论

允许开始第一批实施。先重做公共壳层、主页和画布库，再进入生成工作台页面，避免一次性修改所有业务组件造成不可定位回归。
